## 项目状态

V2 使用 Vite + TypeScript 组织规则、事件、状态和界面，目前仍在持续开发。基础角色、入学前流程、固定与随机事件、月份推进、属性抵抗、待办/历史事件、游戏日志、设置和调试入口均已接入。

科研工作站已支持开启论文、想 idea、做实验、写论文、投稿、审稿结算、引用增长和论文推广；看论文、打工、休息，以及商店的购买、出售、升级和订阅操作也已接通。

同学加入后开启论文，每2个月自主科研一次，复用玩家的分数、衰减、会议投稿、审稿和引用规则。科研协作消耗 SAN，按玩家科研加随机0～5推进协作条，每月再加同学默契；每满100后双方自动帮助，各最多保留一次待用机会。参与同学的论文接收后计入非一作成果。导师初始科研积累20、经费0，横向每月一次消耗SAN5换取经费1；有经费时每月消耗1并增加5%科研积累，全组论文去重贡献积累。每年3月按门槛与限项申请、8月获批，带来经费和职称晋升，详见[导师规则](docs/ADVISOR_SYSTEM.md)。恋人每月可选择一次玩耍、学习或购物约会，三条进度独立结算循环奖励，详见[恋人规则](docs/LOVER_SYSTEM.md)。求职和大论文事件可通过调试入口查看并结算进度，但尚未接入自然月度调度；求职 offer 记录、大论文与毕业的联动也未完成。角色成就只在开始页展示，尚无局内判定、奖励或解锁。当前没有存档功能，刷新或关闭页面会丢失本局进度。

基础结局已接入：不堪重负、穷困潦倒、逐出师门、被孤立、延毕、主动退学，以及硕士毕业、博士毕业。培养期仍为68个月，期满处理完到期事件后按当前学位科研分要求结算；四项生存属性跌破零会提前结束，入学后也可在设置里确认主动退学。事件时间轴末尾单独设“结局”页，以可关闭、可重新打开的单幕卡片展示叙事、触发原因、属性和成果，便于截图。结束后保留各栏目与历史事件供查看，停止游戏操作和月份推进；暂不包含高级结局、成就解锁或生涯回顾，详见[基础结局规则](docs/ENDINGS.md)。开发检查开关当前已启用，入学前会显示各栏目并开放部分操作，这不代表正式的解锁流程。

## 当前玩法

- 以月份为单位推进研究生阶段，先处理阻塞事件，再进入下一月。
- 在入学前流程中联系讲师、查看研究组信息并确认导师。
- 分配每月行动次数，推进论文、看论文、打工或休息，同时留意各项操作的 SAN 消耗。
- 完成投稿后等待审稿结果，查看成果与引用，并按需要购买设备、咖啡和 AI 服务。
- 处理教师节、奖学金、寒暑假、学年总结、年会等固定事件。
- 面对按规则抽取的随机事件，并观察属性抵抗、事件效果、Buff 和游戏日志。
- 在设置中点击“打开调试面板”，使用独立浏览器窗口检查属性、月份、论文、人际和事件链。调试窗口与主游戏实时同步，可单独移动和调整大小；关闭调试窗口不影响本局，主游戏关闭或刷新后原调试窗口停止操作。浏览器需要允许本站弹出窗口。

## 本地运行

需要 Node.js 20.19+ 或 22.12+。

```bash
npm ci
npm run dev
```

然后打开终端显示的本地地址。也可以使用 Windows 下的 [一键启动游戏.bat](./一键启动游戏.bat)。

常用命令：

```bash
npm run typecheck
npm test
npm run build
npm run verify
```

`npm run verify` 会依次运行类型检查、完整测试和生产构建。GitHub Pages 的构建入口位于 [.github/workflows/deploy-pages.yml](./.github/workflows/deploy-pages.yml)。

## 访问统计

开始页和游戏信息页依次显示“访问 总数（今日）”“访客 总数（今日）”“游玩 总数（今日）”。参考 V1 的统计口径，沿用 Supabase `increment_counter` / `get_counters` 接口，V2 使用独立的 `phd_simulator_v2_` 计数器及本地存储键，不与个人主页或 V1 混算。接口使用与个人主页相同的公开匿名密钥。

“访问”按页面打开或刷新计数，切换栏目、开局、重开和游戏内操作不重复计数。“访客”通过当前浏览器的本地标记每天去重，每天首次访问时总数和今日各加一次；总数为每日访客的累计，同一浏览器跨日会再次计入。“游玩”按已产生结局的局数统计，毕业、延期及属性耗尽等提前结束都计一次；开局或中途重开不计，反复查看同一结局不重复计数。当天按北京时间划分，游玩归入产生结局当天。

访客总数保留之前的累计值，从本次更新起按每日去重口径继续累加，不重置或推算历史数据。旧版今日访客标记会沿用，避免升级当天重复统计；旧缓存缺少游玩字段时显示 `--`，读到服务器后更新。清除浏览器数据、无痕模式、换浏览器或禁用存储会影响去重，统计不代表精确的真实人数。

仅生产构建在 HTTPS 环境记录访问。本地开发与 HTTP 预览只读取总数，避免调试流量进入正式计数。接口失败时保留已读取的缓存；没有可用数据时显示 `--`，跨日后不会把昨日缓存当成今日数据。并发标签页在支持 Web Locks 的浏览器中共用访客去重锁。

## 开发约定

- `vibe/` 是 V1.5 的行为与内容参考，`vibe2/` 是当前 V2 工程。
- V2 是新开发项目，不兼容旧存档；当前状态只保存在内存中，尚未实现进度保存与恢复。
- 暂未实装的系统保留必要的展示 UI 和调试数据，但不伪造可执行的游戏动作。
- 删除或暂缓的代码、状态和测试必须同步记录在 [docs/DEFERRED_FEATURES.md](./docs/DEFERRED_FEATURES.md)。

## 开发记录

V2 延续 V1 的 AI 辅助开发方式，采用按模块拆分的 TypeScript 工程。仓库提供类型检查、自动化测试和生产构建命令，GitHub Pages 部署前会运行 `npm run verify`。本地修改后应执行相应检查，并核对受影响的事件、状态或界面。
