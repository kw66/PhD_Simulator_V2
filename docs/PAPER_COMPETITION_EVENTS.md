# 论文竞争事件

## 事件和目标

- 随机事件 17：被抢发idea，仅选择 idea 分大于 0 的一作论文。
- 随机事件 18：新SOTA，仅选择实验分大于 0 的一作论文。
- 两者均只选择草稿或会议审稿中的论文，排除期刊修改中、已发表和非一作论文。
- 事件出现时从符合条件的论文中等概率随机选择一篇，三幕保持同一目标。其他论文不受影响。

## 三幕与效果

第一幕发现竞争工作并点明论文题目，第二幕选择应对方式，第三幕显示结果并确认。所有 SAN 与分数变化在第三幕确认时结算，不消耗行动点。

| 选项 | SAN 消耗 | 对应单项分数倍率 |
| --- | --- | --- |
| 装作不知道 | 0 | 0.25 |
| 狡辩二者不同 / 选择性对比 | 1 | 0.5 |
| 小幅修改 | 3 | 0.75 |
| 大幅修改 | 6 | 1.25 |

- 抢发事件的第二项是在相关工作里强调差异；小幅修改改变动机切入点，大幅修改结合对方方法继续创新。
- 新SOTA的第二项只展示能胜过对方的数据集和指标；小幅与大幅修改均改变方法，再重新验证实验表现。
- 只乘以目标论文的 idea 或实验分，四舍五入，原有正分最低保留 1 分。SAN 为固定消耗，不应用科研杂活减免、季节或疾病倍率。
- 按确认时目标论文的当前分数结算；若目标已删除、已发表、进入期刊修改或不再有对应正分，则本次不扣分也不扣 SAN，不另选论文。
- 三幕中的选项效果和结果预览随稿件状态即时更新；无效目标显示跳过原因，不再显示已经失效的修改结果或消耗。历史记录保留确认时的真实结果。
- 仍被未完成事件引用的论文编号不用于新稿，避免同月丢弃并新建论文时把旧事件转移给新稿。
- 结果页将目标论文、审稿说明与数值结果分开展示；结算栏采用 `SAN-1｜idea×0.5（40→20）` 等紧凑格式，无消耗时省略 SAN 项。
- 不更改投稿分数快照或已计算的审稿结果。会议接收仍使用原投稿分数；拒稿后保留受影响的当前稿件，再按原规则获得审稿反馈。

## 后台等待

- 两个事件均进入普通年度随机池，不因暂时没有论文而从候选池排除。
- 抽中时无目标，仅记录后台待触发项，不创建可见待办、不写玩家日志、不阻塞游戏，也不提前绑定论文。
- 每次游戏操作结算后检查条件，包括科研操作、事件加分、拒稿、撤稿和月度变化。有符合条件的论文就立即进入正常事件队列，不再次判定概率。
- 同类事件最多保留一个后台待触发项，跨学年保留；隐藏或已排队的事件不会在新学年再次积攒同类事件。
- 抽取时占用一次随机事件机会并计数，之后显现不重复计数。两个不同事件同时满足条件时分别入队，按正常队列顺序处理。
- 事件已经出现后，删除目标不会重新储存或转移本次事件；结束后仍遵循年度去重规则。
- 调试事件栏提供同名入口，使用相同的目标条件和后台等待流程，不自动创建测试论文。

## 保持不变的事故事件

- 数据丢失仍仅在存在有进度的未投稿草稿时进入候选池，不积攒后台事故。
- 显卡故障仍按普通事件立即出现，不检查玩家论文；它影响公共设备与维修相关结果。
