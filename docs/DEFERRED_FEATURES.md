# 暂缓与删除功能清单

更新时间：2026-08-26

## 用途

本文件记录 V2 开发阶段从运行代码中删除或暂缓的功能，避免以后恢复玩法时只能从历史代码中反查。

- `已删除实现`：产品当前不会执行，也不应保留仅供测试调用的旧逻辑。
- `保留展示`：入口、面板和已完成的 UI 样式仍在，但操作按钮为禁用预览态。
- `恢复要求`：恢复前先核对 `vibe/` 中的真实规则，再按 V2 架构重新实现，不直接复制旧代码。
- V2 是新开发项目，不承担旧存档兼容。

## 开发阶段临时显示开关

当前测试阶段在 `src/core/v2-development-flags.ts` 中启用了
`SHOW_ALL_MODULES_DURING_DEVELOPMENT`。它只用于开发检查：入学前也直接显示科研、人际、商店和成果栏目，并允许商店按钮在入学前响应，便于集中检查各面板；其他核心解锁条件和正式游戏逻辑没有改变。

正式发布前必须将该开关改为 `false`，恢复入学前显示“入学后开放”并隐藏未开放栏目的正式体验。

- 事件选项支持明确的禁用原因；疾病事件的买药/就医即使金币不足也保留选择，结算后由统一负值结局规则处理。

上述删除不代表功能永久取消。恢复时应先重新确认规则，并补齐状态写入、日志、边界和端到端测试。

## 2026-08-30 成果审稿机制重构

- 删除 V2 临时使用的 C/B/A `6/12/18` 硬投稿线；idea、实验、写作均有分即可选择任意等级会议投稿。
- 删除“投稿总分 + 玩家科研”对固定接收线的确定性判定；科研只影响日常科研操作产分，不再在审稿阶段重复加成。
- 不迁移旧版 Supabase 历史投稿表、会议冷热、自适应 R/B/BL 调档、动态 P90/P99 和动态影响因子。审稿完全使用本地静态规则，不依赖其他玩家数据或网络状态。
- 每篇论文生成三位审稿人，从八类年度概率池中有放回抽取；单人结果为 Accept / Borderline / Reject，总评 `>=2` 录用、`<=-2` 拒稿，`-1/0/1` 进入论文等级对应的边缘录用概率。
- 参考分由三位审稿人和 PC 录用流程逐分试算，取均衡论文录用概率首次达到 50% 的分数；等级平均值约为 C `20`、B `40`、A `70`，再按会议影响力相对等级平均值缩放。
- C/B 会议使用 `Poster / Oral / Best Paper`；A 类另有 `Spotlight / Best Paper Candidate`，各档位门槛与审稿规则见 `docs/REVIEW_SYSTEM_V2.md`。
- 审稿时使用投稿快照判分，但审稿期间论文当前的 idea、实验、写作仍按热度衰减；退稿时保留衰减后的当前分数，并一次性叠加报告中的修改建议，三位审稿结果保存在论文记录中。
- 中稿科研分仍为 `C +1、B +2、A +4`；SAN、导师好感奖励按接收档位结算，并继续使用同级或更高成果的递减规则。导师好感逐点使用现有属性抵抗。
- 中稿论文移入成果档案并立即释放工作槽；第一作者论文槽可在整个培养周期反复使用。成果档案继续参与引用、国奖、毕业、转博与参会链。
- “数据丢失”的引用惩罚按事件结算时的论文快照写入：当时所有未投稿且已有进度的一作草稿未来引用 `×0.5`；空白草稿、已投稿或已发表论文、非一作论文及未来新建论文均不受影响，也不生成全局 Buff。
- 继续保留 V2 的第一作者/合作论文区分、年度引用、h 指数、i10 指数和推广系统；复杂返修和审稿成就仍暂缓。

## 2026-08-23 实装同步：事件与 Buff

## 2026-08-26 Buff 语义与展示重构

- 删除 `GameState.actionBonuses`、`persistentExtraActions` 和独立 `publicationEffects` 三套重复状态；行动与引用的持续效果统一从 `state.buffs` 读取和消费。

- 效果栏按“生命周期 + 目标 + 效果类型”聚合：加法效果累加；倍率按相对 `x1` 的增减幅线性合并并以 `x0` 为下限，例如两个 `x1.5` 合为 `x2`、两个 `x0.5` 合为 `x0`；相同效果合并来源，负数与小于 1 的倍率统一使用负面样式。
