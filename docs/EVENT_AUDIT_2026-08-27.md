# 事件逻辑与文案审计（2026-08-27）

审计范围：当前主流程中的固定事件、普通随机事件、疾病事件、事件队列、属性抵抗、科研杂活减免、Buff 写入、日志与结算展示。论文、求职、会议衍生关系等暂缓系统单独列出，不按已完成玩法验收。

## 本轮已修复

- “拜入门下”统一为 `SAN -4`；运行逻辑、审阅页、维护记录一致。
- 羽毛球和德州扑克首次胜率统一为 `40%`；历史参加一次 `+10%`，羽毛球拍 `+30%`，上限 `90%`。
- 羽毛球拍展示从旧的“额外判定”改为胜率 `+30%`。
- 指导师弟/师妹在首次发表第一作者论文后立即进入当前学年的候选池，不再等下一学年。
- 国奖申报排除非第一作者论文，避免只计引用的论文占用已申报成果。
- 学年总结修复旧版数值尺度：SAN 提示按 `<6 / <12 / >=12`，好感低档按 `<6`。
- 无实际效果的“无事发生 / 无变化 / 属性 +0”不再单独显示结算框；条件仍保留。
- 同门合作的非一作论文文案改为真实挂名，不再错误描述成参考文献引用。
- 两份事件审阅页统一了可达状态、触发条件、胜率、SAN 数值和 AI 报销结果文案。

## 仍需用户确认的统一规则

1. 关系槽位已满时如何处理新增人物。目前不同事件分别采用“取消整项效果”“只取消新增人物但保留奖励”或“交给其他同学”，尚未统一为放弃/替换流程。
2. 永久成长的强度是否需要统一。重点是“拜入门下”永久写作 `+4`、GPU 最多永久实验与每月次数各 `+4`、装修工位一次提供两项永久 `+1` 和 SAN 上限 `+1`。
3. 导师项目与人际栏导师卡片的项目进度、分工调整和完成奖励仍需在开发人际栏前确认，不应直接按旧提案实现。
