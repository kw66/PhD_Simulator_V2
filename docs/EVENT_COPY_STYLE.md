# 事件剧情文案

本轮审阅：2026-09-23

风格参考：读研之始的“眼下连实验室的门朝哪开都还不知道，你却已经对未来充满了期待。”

## 写法

- 用研究生日常的具体细节表达心情，如邮件附件、组会投影、没写清的实验备注；少用“收获很多”“成长了不少”等总结。
- 幽默来自处境和轻松自嘲，不要求每幕都有笑点；疾病、拒稿、关系破裂和失败结局保留分量。
- 第一幕交代事情；第二幕顺着眼前的情境展开权衡；第三幕呈现选择后的结果。避免每次都用相同的过渡句。
- 通常每幕一至两段，短剧情保留一段。偏长的六至八行剧情只精简一至两行，优先删重复铺陈和无效收尾，保留幽默、信息、选项暗示与转折；不按统一字数机械裁剪，也不为了凑长度重复其他幕的信息。
- 读研之始的第二幕只展示导师信息。审稿信息、属性表、结算数值等继续保持简明，不强加剧情。
- 避免反复以“收好材料、回去继续”收尾，使用贴合本次事件的动作。

## 一致性

- 保留已确认的事件标题、选项和规则；剧情必须对应当前实际效果，不能暗示额外奖励。
- 角色姓名与性别沿用现有生成结果。涉及恋人、论文、合作空位、属性档位及成功失败的内容，分别检查条件分支。
- 不把未完成的安排写成已经实现的结果；注意录取、投稿、审稿、开会的时间顺序。
- 不向玩家讲内部版本对比、待开发安排或代码兜底逻辑。
- 第一、二幕用剧情暗示分支；第三幕结算框直接显示实际条件（如科研 < 6、导师好感 ≥ 6或“同学重逢（30%）”），不使用“准备不足”等评价代替门槛，也不写“xx分支”。概率只写百分比，不追加“概率”二字。通用档位抵抗不单列为事件条件，实际抵抗量保留在结果中。条件与实际效果分开，概率减免等收益仍归入结果。
- 事件本身有出现门槛时，第一幕在剧情后统一显示“💡 出现条件：……”，只写实际出现时间或门槛，不写天赋、抽取权重或内部实现。当前包括固定事件的日历时间、科研经费、科研/社交能力、已发表一作论文、未投稿论文和论文分项分数等门槛；选择分支的条件仍在第三幕结算框显示。
- 修改文本后检查精确文案断言，并抽查桌面和手机上的正文、按钮及各幕预留高度。

## 本轮覆盖

- 随机事件：毕设、审稿、导师项目与约谈、组会、团建、经费、学习、同门合作、师兄师姐指导、署名、新生指导、显卡故障、游戏、数据丢失、抢发 idea、新 SOTA，以及三类疾病。
- 固定事件：入学、教师节、国奖、寒暑假、学年总结、转博、指导新生。
- 会议及后续：年会、论文参会、会场全部活动选项、联培、实习、两类恋人。
- 科研与去向：论文结果、毕业论文推进、四类求职；同时检查事件页展示的毕业与失败结局。
- 天赋触发记录、期刊结算日志等纯信息记录保留原有简明格式。
