# 论文结果与会议统计

2026-10-09 更新。

- 第一幕居中展示会议缩写与年份、全称；会议影响力、投稿数、录用数、录用率同排。下方六类结果只列占比与均分，无“全球统计”标题、参考分、P90／P99或解释段落。缺失数值显示“−”，保留完整表格。
- 第二幕标题为“审稿人意见”，论文标题与投稿时创新／实验／写作／总分表居中。桌面三名审稿人横排，窄屏纵排；拒稿红底、接收绿底、边缘蓝底。展示当次实际计算权重、有效分、阈值、评语与效果，不重新抽取权重。
- 第三幕PC综合意见说明各审稿人的决定、总分及边缘概率，接着展示结果横幅；不重复独立会议名、论文标题或确认提示。分数变化与费用直接复用普通事件结果渲染器，合并为结果标签，取消分数列表与圆角。
- 投稿快照与评审结果固定，SAN与待确认论文分数按当前状态刷新，最终确认才结算；事件历史保留确认时快照。

## 真实玩家统计

- 使用新版独立表，不混入旧版数据库统计。按会议名称、届次、A/B/C等级、规则版本汇总。
- 只上传玩家亲自确认的会议评审结果，不含仍在审稿、撤稿、调试结果和同学自动投稿。每次重投是独立评审；重复回调和网络重试使用同一随机UUID，避免重复入库。
- “投稿数”为已确认结果样本数，录用率为录用数／已评审投稿数；各展示类型比例同样以已评审投稿为分母，各类均分基于投稿时总分。P90／P99不在事件页显示。无相应样本的均分显示破折号。
- 正式HTTPS构建启用上传与读取，本地开发禁用；加载失败或缺失数值显示“−”，有缓存时保留上次数据。不把错误当成零投稿。
- 打开调试面板后本局后续结果不上传，未发送记录清除；已经上传的正式结果不回删。
- 客户端不能直读写原始表，只可调用校验参数的记录RPC和聚合读取RPC；不收集玩家姓名、留言身份或论文题目。客户端上报不是服务端验证对局，不能承诺防伪造统计。

## 部署

在留言板所在Supabase项目的SQL Editor执行：

`supabase/migrations/20261009_kwgame_v2_conference_stats.sql`

脚本创建独立记录表、聚合索引及两个RPC，并设置RLS与权限。没有修改旧表。执行后再部署前端，统计从新确认的论文结果开始积累；无需回填旧数据。

规则改变时更新客户端规则版本和数据库允许的版本，保留旧记录但分开查询。规则参考分来自游戏评审模型，不是统计录用分数线或保录承诺。
