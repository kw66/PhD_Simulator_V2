## 已有的新系统边界

- 同学加入时立即建稿，次月首次科研；成功科研后做一个月共享项目再继续科研，审稿期间每月做项目。录用当月新开稿并想idea，拒稿当月修改最低项；实验经费不足3则做横向，下月重新选项尝试科研。使用玩家共用的评分、协作分、热度、衰减、会议投稿、审稿和引用规则，只自动投稿会议，详见[同学月度流程](PAPER_COLLABORATION.md#同学月度流程)。
- 科研协作消耗 SAN，按玩家科研加随机0～5推进协作条；加入次月起每月再加同学默契。每满100后双方自动帮助，各最多保留一次待用机会，按完成时帮助方科研加分，记录人物 ID 和姓名；同学关系积累条已移除。
- 玩家实际贡献给同学论文后，论文录用才计入玩家的非一作成果；同学帮助玩家论文不改变玩家的一作身份。
- `fellowAdditions` 经正式行动结算新增同学后，已有 `ensureFellowPapers` 接续建稿，不需要给每个入队事件另写一套论文循环。
- 事件有 `paperCollaborations` 结算接口，但当前事件定义没有直接提供这一效果；现有讨论类事件主要仍发放玩家行动 Buff。

## 后续逐项修改时的检查点

- 按 E01～E15 编号逐项讨论；确认后再勾选，更新对应事件文本、规则提示和文档，保留既定标题及姓名生成规则。
- 区分“自身学会了方法”的行动 Buff 与“对方实际贡献”的协作分，避免一种行为同时领取两套重复奖励。
- 双向协作的获得频率继续受任务条控制；事件是否额外提供一次机会需单独定值，不把每次交流都变成直接累加。
- 人物与论文使用稳定 ID；重复事件是遇见同一人还是认识新人、普通关系满员时是否只能短期合作，都需明确。
- 第二幕明确目标、占位和成本；第三幕按当前关系、论文状态重新校验。中途停止合作、换论文、投稿或论文录用，不得串人、串稿或重复结算。
- 新增同学入口已经建稿，不能再额外建第二篇。没有合适稿件时如何保留合作机会，与论文竞争等待机制分开规定。
- 非一作成果来自实际参与的同学论文，接收、引用和天赋奖励都只结算一次；关系解除后保留已形成的贡献与成果。
- 明确同学月度自动推进与事件任务是否冲突；未经确认，不借此次联动添加同学 SAN、社交、导师好感等独立属性。
