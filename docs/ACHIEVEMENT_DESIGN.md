# 成就系统规则

更新：2026-10-16。本文描述本地结算与全球达成统计；完整条件及奖励见 [全部成就清单](ROLE_ACHIEVEMENT_ROSTERS.md)，不保留撤回的候选方案。

## 展示与角色范围

- 开始页始终显示全部成就，不随选中角色筛选；对象标签只限制完成资格和奖励对象
- 卡片两行分别显示名称与条件、奖励；悬浮框显示各角色的首次完成日期
- 同一个共享成就允许多个符合条件的角色完成。首次完成发奖，后续角色仅补记录，不重复发奖
- 硕士毕业、博士毕业按角色使用不同ID，分别完成、分别奖励该角色倍率+1
- 正位、逆位、特殊、诅咒分别判断；特殊角色不因底层mode而被当作普通正位
- 结局以“图标＋名称”预览本局将新增的完成记录，含本局首次用另一角色完成的共享成就；点击“结算并重开”后才正式记录

## 达成与结算

游戏运行时积累证据。自然结局或主动退学先显示成就、经验和升级预览，不改变账号；仅点击“结算并重开”才统一发奖、写入完成日期并开始新局。仅明确要求毕业的条件必须毕业。

返回开始页、刷新、继续游戏或读取结局存档均不结算，也不重复计作新开局。未结算的结局允许读取月初存档继续本局；回溯会完整替换本局成就证据、峰值、累计计数、收集集合及待上传统计，并删除该时间点之后的快照，不能保留被撤销分支的达成记录。已结算账号中的其他局记录不受回溯影响。

- “达到”按局内峰值及大于等于门槛处理，不要求结局仍保留；多属性分别记录峰值
- “硕士期间”只计转博前，不将转博奖励计入；不要求最终转博或毕业
- “始终小于6”检查最高值严格小于6；“SAN始终高于12”检查最低值严格大于12
- 累计生命上限提升只累计实际正向增量，不计初始上限，也不抵扣后续下降
- 高分论文Ⅰ/Ⅱ排除协作分；自然风干要求同篇论文三项因时间衰减至1
- 经费大户只统计硕士期间实际为玩家支出的导师经费，不计同学支出、经费增加或剩余金额
- 睡得好香统计主动休息及生病时宿舍休息的实际SAN恢复，不计月初及椅子自动恢复
- Offer取得即计入，不要求保留到结局；四个入门就业挑战各提高一档，分别要求大厂算法岗、央企总部业务主管、省直二级主任科员、211讲师及以上
- 连续3年同一会议按会议年份判定，不能用同年重复发表替代
- Buff之神检查同一时刻生效的效果类型，不能将不同月份的效果累计凑数

打开调试面板会永久取消本局成就、经验和后续统计资格。关闭调试不能恢复；已上传记录保留，未上传的本局记录清除。内部机制计数仍供玩法与测试使用。

## 奖励

- 未特别注明的成就奖励经验+5；自立自强也为经验+5，不再奖励天赋点
- 经验奖励受受奖角色结算前的经验倍率影响，同次结局新取得的倍率不追溯放大本次奖励
- 角色专属奖励该角色；限定类别奖励该类别角色；通用奖励所有角色，包括尚未解锁的角色
- 五类收集成就各奖励全体角色天赋点+1，是当前仅有的成就天赋点奖励
- 奖励以成就ID去重；结局重复预览、换角色再次完成、重新读取记录均不能再次领取
- 点击“结算并重开”时，角色解锁与成就奖励同次结算；角色经验、倍率、额外天赋点、解锁状态和本局结算标识在同一个本地账号写入中保存。写入失败时保留本局存档，不开始新局

测试满级、全解锁已关闭。新账户角色等级0，仅大多数初始解锁，其他角色按成就解锁；天赋仍由玩家在开始页手动分配。

## 跨局收集

五类收集仅在合格结局点击“结算并重开”时将本局集合合并到账号，跨局跨角色累计；结局预览与返回开始页不会提前合并。悬浮框展示尚未取得的项目。目录取自游戏可获得内容，不能根据玩家观察到的项目动态缩小目标。

| 收集项 | 统计口径 |
| --- | --- |
| Buff | 实际可获得的效果类型；相同效果的不同数值、持续时间和来源实例合并，不含调试及无正常获取途径的旧接口 |
| 商品 | 装备各级、椅子及咖啡机升级、配件、咖啡和AI；同一AI供应商不同年份合并 |
| 会议 | 所有会议的已发表论文，合作论文计入；ICCV与ECCV各计一种 |
| 旅行 | 实际亲自到访会议城市，含VALSE明确地点；代贴、仅预约和未指定“外地”不计 |
| 方向 | 所有研究方向的已发表论文，合作论文计入 |

收集成就是账号级完成，已完成后不会在之后每个角色结局重复播报或生成新的收集完成日期。

## 全球达成率

- 已接入kwgame数据库，卡片使用当前统计纪元的全球完成玩家数除以所有开局玩家数；与上方个人成就计数分开
- 玩家沿用浏览器中稳定的匿名访客UUID；同一玩家用多个角色完成同一成就，全球分子只计1人，各角色首次完成日期分别记录
- 所有成就共用当前纪元开过局的匿名玩家去重人数，不按角色、类别或是否结算筛选。同一浏览器换角色、重开或恢复存档不增加人数；打开调试前已经登记的开局不追溯撤销
- 有效非调试开局或恢复局时幂等登记玩家；成就结果仅在“结算并重开”后上报，没有新成就也提交空列表。结局预览、返回开始页、读档和已撤销分支不会提交完成记录
- 上报从账号持久化outbox交给独立成就队列，离线或刷新后重试沿用同一runId；服务端只接受同内容重试，不能追加该局其他分支的成就
- 全部成就一次读取，缓存十分钟；切换角色、成就分页及单张卡片渲染不请求数据库，没有轮询。读取失败保留可用缓存，无数据或分母为0时显示“—%”
- 本地奖励仍按成就ID只发一次，全球统计不承担账号登录、云存档或奖励发放

服务端使用`phd_simulator_v2_achievement_catalog`、`phd_simulator_v2_achievement_runs`、`phd_simulator_v2_achievement_completions`和`phd_simulator_v2_achievement_players`四张表，通过`record_phd_simulator_v2_achievement_start`登记开局玩家、`record_phd_simulator_v2_achievement_run`提交结算，使用`get_phd_simulator_v2_achievement_stats_v2`读取聚合。匿名用户不能直接读写四表。客户端入口为`src/app/v2-achievement-stats.ts`，纪元边界、部署和数据库验证见[在线统计](ONLINE_STATISTICS.md)。

服务端成就资格目录与游戏共享来源。运行`node scripts/sync-achievement-stat-catalog.mjs --check`检查184项成就、20个角色的范围是否一致；修改成就ID或资格范围后应同步数据库目录。

运行 `node artifacts/check-achievement-scopes.mjs --docs-only` 可从当前规范目录重新生成清单，不启动浏览器；去掉该参数会追加卡片布局检查。
